# SCUM 界跃 / SCUM Rift 0.5.0 社区测试版

这是功能仍在完善的社区测试版，很多功能尚未完善或开放，建议主要用于启动已安装 MOD 的游戏。

本版本面向 Windows x64，发行包自带 .NET 10 运行环境。请完整解压后运行 SCUMDevLauncher.exe，不能只复制一个 EXE。程序以普通用户权限运行。

## 首次使用

1. 打开“设置”，选择 SCUM 安装根目录。正确目录下应有 `SCUM\Binaries\Win64\SCUM.exe`。
2. 点击“保存目录”；也可先尝试“自动检测”。找到多个位置时，请自行选择需要使用的一份游戏。
3. 使用自己的 Steam 账号完成登录。点击“启动游戏”后，启动器会先检查 Steam 会话是否就绪；不需要反复点击。
4. 首次使用建议先测试一个小模组，再验证真实游戏和服务器的兼容性。

当前已验证环境：Windows 11 专业版 64 位（10.0.26200）。其他 Windows 版本、多显示器 DPI 和真实游戏版本需要继续验证；不把一次编译视为全部环境兼容。

## 界面语言

在“设置 → 语言 / Language”中选择简体中文、繁體中文、English、日本語、한국어，立即生效，不需要重新启动。第一次打开跟随 Windows 界面语言，其他系统语言使用英文；之后优先使用玩家保存的选择。语言和主题共同保存在用户数据目录的 `ui.json`，相互独立。

主要页面、主题名、按钮、拖入提示、安装进度与结果、确认说明和启动器自身错误支持五种语言。操作日志保留生成时的语言；切换后空闲状态显示“就绪”。模组作者提供的名称、介绍、分类、文件名和路径保留原文；Windows 原生弹窗按钮及系统产生的错误由系统语言决定。安装、刷新和启动游戏期间语言菜单暂不可用，任务完成后即可切换。

English: Settings → Language. Changes apply immediately and are saved. Fully extract the package and run `SCUMDevLauncher.exe`; select and save your SCUM folder before importing mods. Drop PAK, UE4SS C++ DLL, ZIP, 7Z or RAR files onto the window with the game closed.

日本語：設定 → 言語 / Language で切り替えます。変更はすぐに反映され、保存されます。パッケージをすべて展開し、`SCUMDevLauncher.exe` を起動してください。SCUM フォルダーを選択・保存し、ゲームを終了してから PAK・UE4SS C++ DLL・ZIP・7Z・RAR をウィンドウにドロップします。

한국어: 설정 → 언어 / Language에서 변경합니다. 즉시 적용되며 저장됩니다. 패키지를 완전히 압축 해제한 후 `SCUMDevLauncher.exe`를 실행하세요. SCUM 폴더를 선택하고 저장한 뒤 게임을 종료하고 PAK, UE4SS C++ DLL, ZIP, 7Z, RAR 파일을 창에 끌어 놓으세요.

## MOD 缓存与纯净模式（0.5.0）

1. 关闭游戏，在“本地管理”点击“切换纯净模式”。标准加载位置中的 MOD 和加载环境移至游戏根目录下的 `.SCUMRift-cache`；无需卸载或重新下载。
2. 想继续玩 MOD 时，点击“恢复 MOD 模式”，文件回到原位，配置和原来的启用／禁用状态保持不变。此前禁用的 MOD 不会被顺带启用。
3. “打开 MOD 缓存区”可查看位置。缓存区使用内部编号保存文件，由管理清单对应原位置。**不要手动改名、移动或删除缓存和管理记录**；这两个位置须一起保留。

暂存范围：`SCUM/Content/Paks/~Mods`、`SCUM/Content/Paks/LogicMods`，以及 `SCUM/Binaries/Win64` 下的 `ue4ss`、`Mods`、`UE4SS.dll`、`UE4SS-settings.ini`、`UE4SS_Signatures`、`dwmapi.dll`、`xinput1_3.dll`。目录内的手动文件与配置也会一起保留。其他位置的注入工具、自定义加载器、放在 Paks 根目录的非标准模组，以及已替换的官方游戏资源不在自动还原范围；因此此功能不能证明整份游戏与官方原版完全一致。存在 `override.txt` 自定义 UE4SS 路径时会停止切换。

移动发生在同一游戏目录所在卷，无需另存一整份 MOD；切换前读取哈希，体积大的 MOD 校验会花时间。恢复前检查缓存完整性。游戏运行中禁止切换，纯净模式下须先恢复再安装或修改 MOD。如果原位置出现新文件，会停止恢复并保留两边内容，请先把新文件移到其他位置再恢复。

意外退出后，重新打开启动器或在“更多 → 检查并恢复”回滚未完成的切换；完成的纯净模式会一直保留到主动恢复。缓存期间换用 0.4.0 或更早版本会缺少对应的恢复功能，**降级前必须先用 0.5.0 恢复 MOD 模式**。转移整份游戏到新路径时，也应先恢复再移动。

English: Switch to vanilla caches standard PAK and UE4SS files inside the game folder; Restore MOD mode returns them with their original state. Keep both the cache and its journal. Restore in 0.5.0 before downgrading.

日本語：バニラモードへの切り替えで標準 PAK・UE4SS ファイルをゲーム内のキャッシュへ退避し、MOD モードで元に戻します。キャッシュと管理記録は削除しないでください。旧版へ戻す前に 0.5.0 で復元してください。

한국어: 순정 모드로 전환하면 표준 PAK 및 UE4SS 파일을 게임 폴더의 보관함으로 옮기고 MOD 모드에서 복원합니다. 보관함과 관리 기록을 삭제하지 마세요. 이전 버전을 사용하기 전에 0.5.0에서 복원하세요.

## Steam 与游戏启动顺序（0.5.0）

点击“启动游戏”后，Steam 未运行时会先启动。启动器检查有效客户端进程、同会话的界面进程和已登录账号，连续稳定约 0.6 秒后启动游戏；每 0.15 秒检测一次。Steam 已经就绪时无需固定等待几十秒；登录、更新或首次初始化尚未完成时显示当前等待阶段。模组完整性检查与 Steam 等待同时进行，两项均通过才创建游戏进程。

底部“取消任务”可停止启动前的等待，最多等待 120 秒；仍未确认就绪时取消本次启动，不会到时强行启动游戏。Steam 状态或权限无法确认时，请在 Steam 中完成登录／更新，并让 Steam 与启动器使用相同的普通用户权限后重试。此判断依据本机可读信号，不能保证每种 Steam 版本和网络条件下的精确时机；实际冷启动速度仍需玩家环境试用。

MOD 模式保留既有启动参数；纯净模式不添加 MOD 专用参数。游戏创建后检查约 1.5 秒再最小化启动器。`launcher.ps1` 仅保留只读诊断，旧脚本的启动入口已停用，统一由窗口执行目录锁、缓存检查和 Steam 就绪检查。

## 安装与管理模组

- 将 `.pak`、UE4SS C++ 模组 `.dll`、`.zip`、`.7z` 或 `.rar` 文件直接拖到启动器窗口，松开鼠标后自动识别、解压、检查 PAK 并安装；也可点击“导入模组 / 压缩包”多选文件。游戏必须先关闭，并已设置正确目录。本地文件会直接导入安装，无需重新联网下载。
- 压缩包可有多层普通目录；识别其中的 PAK、UE4SS C++ 模组和加载环境核心；说明文件会忽略。PAK、DLL、离线环境可同批校验并一起提交，失败会恢复原文件。PAK 目标仍是 `SCUM\Content\Paks\~Mods`，DLL 的目标见下文。
- 同一批内有同名 PAK 时会停止，请只选择需要安装的一套。遇到游戏内的同名手动文件，会要求确认备份；确认后安装，卸载时恢复原文件。
- ZIP、7Z、RAR 必须完整且未加密。暂不支持分卷、压缩包套压缩包、文件夹拖入、网页链接、自动执行安装器、Lua 独立模组、UTOC/UCAS 等加载方式。普通 DLL、32 位或托管 DLL 不会当作 UE4SS 模组安装。
- 每次最多 128 个 PAK、10000 个压缩条目，默认总展开上限 20 GiB（受配置体积上限约束），支持取消。不能将任意文件改后缀伪装成模组。PAK 自算哈希用于传输和安装一致性，不证明作者身份。
- 新的本地导入文件显示版本 0.0.0；本地内容替换已管理模组时会标记为本地版本，避免错误显示为作者已发布的版本。已禁用的模组更新后仍保持禁用。
- “模组目录”展示已配置清单，可搜索名称、作者与简介，按分类、安装状态筛选，查看版本、依赖、冲突与游戏兼容范围后安装或更新。
- 远程模组托管方式和正式地址尚未决定。社区包因此不内置开发机模组来源；这不影响本地 PAK、UE4SS DLL 的安装与管理。
- “校验文件”读取完整文件并检查哈希和结构。“待校验”只代表存在记录且大小匹配，不能等同于完整性通过。游戏启动前也会完整检查启用的已管理模组。
- 禁用会把文件移出游戏加载目录；启用恢复文件。更新后保留最近一版可用备份，可“恢复上一版”。
- “卸载”只处理已纳管且未被外部修改的文件。被其他启用模组依赖时，会要求先处理依赖方。
- 已有手动安装文件标记为“未纳管”。遇到同名文件必须明确确认后才备份接管，卸载时会核对并恢复原文件。
- 安装和修复可能替换当前受管理文件。外部改动需要保留时，请先另行备份，再执行重新安装/修复。
- 游戏运行期间不能写入模组。可正常关闭游戏；等待超时后只有明确选择强制关闭才会结束进程。

PAK 结构检查只判断受支持格式的基本结构，不是恶意内容扫描。作者未声明的依赖、PAK 内部资源覆盖、未纳管文件的兼容性以及服务器策略，需要作者和玩家确认。

## UE4SS DLL 模组与离线环境

1. 关闭游戏，在启动器中选好游戏根目录；游戏状态卡会显示是否检测到 UE4SS，并提供“UE4SS 模组目录”入口。
2. 拖入作者发布的命名 DLL，例如 `Example.dll`，会安装为 `Mods/Example/dlls/main.dll`。程序只读取 PE 元数据，检查 Windows x64 原生格式、`start_mod` / `uninstall_mod` 导出以及对 UE4SS 的导入符号，不在启动器进程中加载或执行这些 DLL。
3. 单独的 `main.dll` 如位于 `模组名/dlls` 目录会采用上级名称；否则弹窗输入作者提供的模组名称。名称可能影响模组自己的路径，请使用作者名称。带依赖 DLL、配置和资源的模组，建议保持 `Mods/模组名/dlls/main.dll` 及同级资源结构，打成 ZIP/7Z/RAR 整体拖入；只拖一个 DLL 不会自动搜索旁边的依赖。
4. 支持 `SCUM/Binaries/Win64/UE4SS.dll` 与 `SCUM/Binaries/Win64/ue4ss/UE4SS.dll` 两种标准布局，后者优先。模组安装到该 UE4SS 所属的 `Mods` 目录。`override.txt`、自定义 ModsFolderPaths/ControllingModsTxt/WorkingDirectory 暂不支持自动安装，会提示恢复标准布局。
5. **未安装 UE4SS 时，先拖入适用于当前 SCUM 与模组的完整 UE4SS 离线压缩包。** 也可以把完整离线包、DLL 模组、PAK 一起拖入。离线包须有 UE4SS.dll 和根目录代理 DLL（支持 dwmapi.dll、xinput1_3.dll）；会导入核心、代理、设置和签名配置，不会顺带启用包内示例 Lua 模组。启动器不自动联网下载、不附送 UE4SS，也不根据“最新版本”猜测游戏兼容性。已存在另一种目录布局时不会再安装第二套。
6. 自动在 `Mods/mods.txt` 的 Keybinds 前登记启用，保留无关条目、注释、BOM 和换行；导入包中的 enabled.txt 不会作为强制启用标记。已有同名手动文件、启用项或标记需要确认后备份接管。
7. DLL 模组可校验、启用、禁用、更新、恢复上一版及卸载。禁用会移走已管理文件并关闭启用项，更新保持原禁用状态，卸载恢复接管前文件和启用项。外部更改、备份损坏、路径链接、游戏运行和任务锁都会受到检查。卸载或回滚加载环境前须先移除依赖它的模组，加载环境不支持单独禁用。
8. 客户端/服务端组合包会选择前两层路径中标记为 Client 的客户端内容并忽略 Server；独立 Server 包会拒绝。没有标准标记、复杂嵌套或作者自定义布局的包请先整理为客户端标准目录，避免选错版本。

导出符号匹配仅是接口检查，不证明 DLL 无恶意代码，也不保证游戏内部接口、UE4SS ABI 或所有模组依赖兼容。请使用可信作者和匹配版本；本版仍需真实游戏加载与服务器联机测试。已管理的配置/资源文件若被玩家或模组改写，完整性检查可能提示改动；需要保留时先备份，重新导入可能重置这些文件。全新生成且未纳管的文件不会自动删除。不要用 0.3.0 或更早版本管理 0.4.0 的 DLL 安装记录或恢复事务。

## 数据保存位置

游戏配置、主题、清单、缓存和日志：`%LOCALAPPDATA%\SCUMDevLauncher`。首次读取发行目录的种子配置时，会保留迁移前副本于 `migration-backup`。已有用户配置优先，不会每次启动被发行包覆盖。

每份游戏的安装记录、禁用文件、暂存和备份：`SCUM\Content\Paks\.SCUMDevLauncher`。不要手动删除或复制部分管理文件；保留完整目录有助于卸载和故障恢复。旧版备份仅保留有记录的上一版、接管前原文件和正在恢复所需的文件。

Steam 板块仍沿用程序目录内原有的 steam.json/avatar.png 方式。社区包不带任何人的账号文件；个人试用目录可能保留原有绑定，禁止直接转发个人目录。

程序目录含本体和运行环境，应放到自己的用户目录，避免允许其他普通用户修改。关于页提供目录权限提示；启动器不会递归修改磁盘权限。

## 取消、失败与中断恢复

- 底部“取消任务”会中止可取消的读取与传输；已开始的必要文件提交会先完成或恢复，再返回。
- 获取失败会有限重试，并尝试其他合法来源。只有网络文件、大小、SHA-256、基础结构全部通过后才提交。
- 支持同次任务内有效 Range 续传；服务器忽略 Range 时重下。跨次启动不保留下载断点。单任务总超时 30 分钟，无进展超时 30 秒。
- 断电或意外退出后，请先关闭游戏再打开启动器。存在未完成事务时会恢复原文件和安装记录；“更多”也有“检查并恢复”入口。
- 恢复失败时不要清理管理目录。先导出诊断，再保留现场处理。
- 配置损坏时不会猜测开发机游戏路径。可在设置里恢复配置备份，或重新选择并保存目录。
- 日志入口在设置页；导出诊断默认仅包含日志和运行环境，不含账号文件与完整配置，也不会自动上传。

## 升级与发行包验证

在“更多”选择“验证离线发行包”，指定完整解压的新包目录。启动器使用编译进程序的发行公钥检查签名清单，并检查文件大小、哈希及额外文件。校验完成后关闭旧版，在独立目录运行新版；本版没有自动覆盖自身或联网更新。

验证应使用尚未运行、未修改的干净发行包。个人包启动后，原 Steam 模块可能更新程序目录文件，因此不适合作为干净发行包继续核验或分发。

远程清单必须使用 HTTPS，且 JSON 和同地址路径追加 `.sig` 的签名都通过验证；远程清单不能引用本地文件。完整校验的新清单才写入缓存，离线时缓存会再次验证并显示缓存时间。

本项目尚未使用 Windows 受信任代码签名证书。清单签名用于本启动器验证发行内容，不等于 Windows 公认的发布者身份，也不保证消除 SmartScreen 提示。尚未接入的托管服务不产生月费。

## 恢复到旧版

旧使用目录和原源码本次未覆盖。若当前为纯净模式，先在 0.5.0 中点击“恢复 MOD 模式”，再关闭新版运行原目录。若新版管理过模组，建议先在新版中卸载或恢复到所需状态，再切回旧版。旧版不理解新版管理记录和禁用目录。游戏存档并未作为本轮测试对象，也未被本轮操作修改。
